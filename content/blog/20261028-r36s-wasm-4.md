WASM-4 で作った Polygon Metronome を R36S に入れたところ、メニューから選んでもすぐメニューに戻ってしまい、起動しませんでした。原因は、OS に WASM-4 を動かすコアの本体が入っていなかったことです。公式のソースからコアをビルドし、R36S のメニューの「Ports」から起動できるようにしたので、その手順をまとめます。  
コアを同梱した R36S 用パッケージは [https\://metronome.ours-blanc.app/r36s/](https://metronome.ours-blanc.app/r36s/) で配布しています。

## **環境**

* 本体：R36S（基板 R36S-V12、液晶 Panel 4）
* OS：dArkOSRE-R36（2026 年 3 月 8 日版）
* 症状：「WASM-4」のゲームを選ぶと、起動せずにすぐメニューに戻る

## **原因の調べ方**

R36S の OS（ArkOS や dArkOS の系統）は、EmulationStation というメニューから RetroArch を起動してゲームを動かします。どのシステムを何で動かすかは es\_systems.cfg に書かれていて、WASM-4 は次のコマンドでした。

`retroarch -L /home/ark/.config/retroarch/cores/wasm4_libretro.so %ROM%`

メニューの項目と起動コマンドはあるので、最初はコアも入っているものと思っていました。ところが OS のイメージを調べると、wasm4\_libretro.so という名前は設定ファイルやコアの一覧には出てくるものの、コアの本体が見つかりません。  
確かめ方は単純で、WASM-4 のコアならどれも、ゲーム側から呼ばれる関数の名前（blitSub や textUtf16 など）を文字列として持っています。8.3GB のイメージ全体をこれらの文字列で検索して、一度も出てこなかったので、コアは入っていないと判断しました。RetroArch はコアを読み込めずに終了し、メニューに戻っていたわけです。

## **コアをソースからビルドする**

libretro の配布サーバーからビルド済みのコアを入手する方法もありますが、今回は手元の環境から接続できなかったため、WASM-4 公式のリポジトリ [aduros/wasm4](https://github.com/aduros/wasm4) からビルドしました。runtimes/native に libretro 向けのビルド設定が入っています。R36S の CPU は 64 ビットの ARM（aarch64）なので、Linux の PC でクロスコンパイルします。

```
sudo apt install gcc-aarch64-linux-gnu g++-aarch64-linux-gnu cmake
git clone --recurse-submodules https://github.com/aduros/wasm4
cd wasm4/runtimes/native
cmake -S . -B build-a64 -DCMAKE_BUILD_TYPE=Release \
  -DLIBRETRO=ON -DWASM_BACKEND=wasm3 \
  -DCMAKE_C_STANDARD_LIBRARIES=-lm \
  -DCMAKE_SYSTEM_NAME=Linux -DCMAKE_SYSTEM_PROCESSOR=aarch64 \
  -DCMAKE_C_COMPILER=aarch64-linux-gnu-gcc \
  -DCMAKE_CXX_COMPILER=aarch64-linux-gnu-g++
cmake --build build-a64 --target wasm4_libretro
```

できあがった wasm4\_libretro.so は 235KB で、依存するのは標準の C ライブラリと数学ライブラリだけ、必要な glibc は 2.17 以上です。64 ビット版の RetroArch を使う R36S 用の OS なら、そのまま読み込める条件です。

### **ハマったところ：数学ライブラリのリンク漏れ**

最初のビルドでは、読み込んだ瞬間に undefined symbol: powf で失敗しました。ビルド設定が数学ライブラリ（libm）をリンクしていなかったためです。RetroArch 自体が libm を読み込んでいるので R36S 上では気づかない可能性もありますが、確実にするため \-DCMAKE\_C\_STANDARD\_LIBRARIES=-lm を付けてリンクするようにしました。

## **R36S に入れる前に動作を確かめる**

同じソースを PC 用にもビルドし、C で数十行の小さな libretro フロントエンドを書いて、カートが本当に動くかを確かめました。やっていることは、コアを読み込んでゲームを渡し、数十フレーム回して A ボタンを押し、画面と音を数えるだけです。

* 画面：160×160、4 色、背景以外のピクセルが 1,948
* 音：停止中は無音、A で再生したあとは無音でないサンプルが 25,845

WASM-4 のコアは音を RetroArch の「オーディオコールバック」で渡すので、フロントエンド側でもそれに対応しないと音が 0 に見えます。ここは一度つまずきました。  
ボタンの対応もソースで確かめました。R36S の A と X が WASM-4 のボタン 1、B と Y がボタン 2 になります。

## **R36S にコアを入れる**

コアの置き場所 /home/ark/.config/retroarch/cores/ は、microSD カードの Linux 用の領域にあります。Mac や Windows からは書き込めないので、R36S の上で動くスクリプトにコピーさせる必要があります。

### **最初の方法：Tools メニューのインストーラ（動かなかった）**

最初は、カードの EASYROMS/tools/ にインストール用のスクリプトを置き、メニューから一度だけ実行してもらう形にしました。ところが実機では、そのスクリプトは一度も実行されませんでした。スクリプトは実行されると必ずカードに記録を書くようにしていたのに、記録が残っていなかったので、実行されていないとわかりました。  
OS の設定を調べると、このメニュー構成には「Tools」というシステムがなく、tools フォルダは「Options」の中の Tools として見える作りでした。手順として「Tools から実行」と案内したのがそもそも分かりにくく、別の手順を踏ませる方式自体がつまずきやすいと考えて、やり方を変えました。

### **うまくいった方法：Ports から起動するランチャー**

R36S の OS には「Ports」というメニューがあり、EASYROMS/ports/ に置いた .sh のスクリプトをそのまま実行します。そこで、メトロノームを起動するスクリプトそのものに、コアを入れる処理を持たせました。

```
EASYROMS/ports/Polygon Metronome.sh
EASYROMS/ports/polygon-metronome/polygon-metronome.wasm
EASYROMS/ports/polygon-metronome/wasm4_libretro.so
```

起動すると、スクリプトは次の順に動きます。

1. 同梱のコアを OS の RetroArch のコアフォルダにコピーする（すでに同じものがあれば何もしない）
2. コピーできなかったときは、同梱のコアを直接使う
3. RetroArch を詳細ログ付きで起動し、メトロノームのカートを読み込ませる
4. 途中の様子と RetroArch のログを EASYROMS/ports/polygon-metronome/log.txt に書く

メニューから選ぶだけで動き、もし失敗してもカードをパソコンに挿せば記録を読めます。この方法で、R36S の実機でメトロノームが起動し、音が鳴ることを確認しました。

1. [配布ページ](https://metronome.ours-blanc.app/r36s/)から r36s-polygon-metronome.zip をダウンロードして展開
2. 中の ports フォルダの中身を、カードの EASYROMS/ports/ にコピー
3. R36S のメニュー →「Ports」→「Polygon Metronome」を起動

### **Mac を使うときの注意**

Mac でカードにファイルをコピーすると、.\_Polygon Metronome.sh のような「.\_」で始まる隠しファイルが一緒に作られます。R36S のメニューではこれが壊れた項目として並ぶことがあるので、コピーしたあとに消しておくと安心です。ターミナルで find /Volumes/EASYROMS \-name '.\_\*' \-delete を実行すると、まとめて消せます。

## **まとめ**

* メニューに戻るときは、まずコアの本体があるかを疑う
* WASM-4 のコアは公式ソースから aarch64 向けにビルドでき、依存も少ない
* 別の手順を踏ませるより、起動するスクリプト自身にコアを入れさせて、記録をカードに残すほうが確実

このコアで動かしているメトロノームについては「Polygon Metronome が携帯ゲーム機 R36S で動くようになりました」、作り方は「WASM-4 でポリリズム・メトロノームを作る」をどうぞ。
