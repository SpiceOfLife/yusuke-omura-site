Web 版の Polygon Metronome を、ファンタジーコンソール WASM-4 で作り直しました。160×160 ドット、4 色、音 4 チャンネルという制約の中で、ポリリズムのメトロノームをどう組んだかをまとめます。言語は AssemblyScript（TypeScript に近い書き方で WebAssembly にコンパイルできる言語）です。

完成したもの：[https\://metronome.ours-blanc.app/r36s/](https://metronome.ours-blanc.app/r36s/)

## **WASM-4 を選んだ理由**

WASM-4 は、昔のゲーム機のような制約を決めた「架空のゲーム機」です。主な仕様は次のとおりです。

* 画面 160×160 ドット、1 画面に使える色は 4 色（パレットは毎フレーム変えられる）
* 音はパルス波 2・三角波 1・ノイズ 1 の 4 チャンネル
* 入力は十字キーとボタン 2 つ、マウス
* カートリッジ（.wasm ファイル）は 64KB まで、保存領域は 1KB
* update() が 1 秒に 60 回呼ばれる

同じ .wasm ファイルが、ブラウザと、RetroArch の WASM-4 コアが動く機械（R36S のような携帯ゲーム機を含む）でそのまま動きます。Web 版のアプリを、ほぼ手を入れずにゲーム機へ持っていけるのが決め手でした。できあがったカートは 13,400 バイトです。

## **タイミング：位相を積み上げて、フレームで鳴らす**

Web 版は Web Audio API で「1 周ぶんの音」を先にサンプル単位で作り、ループ再生しています。WASM-4 にはそうした仕組みはなく、できるのは update() の中で tone() を呼んで音を鳴らすことだけです。つまり拍は 1/60 秒単位でしか置けません。  
そこで、基準の連符の 1 周を 1 とした「位相」を倍精度の数で持ち、毎フレーム足していく形にしました。基準が N 連で BPM が b なら、1 周は N 拍なので、1 フレームで進む位相は b ÷（60 秒 × 60 フレーム × N）です。

```
phase += bpm / (3600.0 * refN());
for (let i = 0; i < MAX_LAYERS; i++) {
  const n = layerN[i];
  if (n <= 0) continue;
  const c = <i64>Math.floor(phase * <f64>n);  // これまでに鳴るべき拍の数
  if (c != lastCount[i]) {                      // 増えたら1拍鳴らす
    lastCount[i] = c;
    const idx = <i32>(c % <i64>n);
    hit(i, idx == 0);                           // 0番目はアクセント
  }
}
```

各連符は「位相 × n の整数部分」が増えたフレームで鳴ります。拍の時刻そのものは常に正しく計算されているので、1 拍の誤差は 1 フレーム（16.7 ミリ秒）以内に収まり、何分鳴らしても誤差は積み重なりません。再生中に BPM や連符を変えても位相はそのまま続くので、拍の流れが途切れません。変えたときは各連符の「これまでの拍数」を計算し直して、同じ拍が二度鳴らないようにしています。

## **音：4 チャンネルの割り当て**

連符は最大 3 つにして、それぞれにチャンネルを固定しました。

| チャンネル | 使い道 |
| :---- | :---- |
| パルス 1（デューティ比 25%） | 1 つ目の連符 |
| パルス 2（デューティ比 50%） | 2 つ目の連符 |
| 三角波 | 3 つ目の連符 |
| ノイズ | 基準の連符のクリック音 |

3 つの連符の 1 拍目は必ず同じフレームに重なるので、1 つのチャンネルを使い回すと音が消えてしまいます。チャンネルを分けておけば、全部が同時に鳴ってもどれも途切れません。Web 版のノイズのクリック音は、基準の連符にだけノイズチャンネルで付けました。  
音程は Web 版と同じく基音 × N です。基音 A3（220Hz）なら 4 連は 880Hz、3 連は 660Hz です。平均律に丸める設定では、MIDI ノート番号に直して四捨五入しています（660Hz は E5 の 659Hz になります）。音の長さは WASM-4 の tone() のエンベロープで決めていて、普通の拍は 7 フレームで減衰、アクセントは 14 フレームで音量も大きくしています。

## **見た目：4 色で 3 つの連符を描き分ける**

4 色のうち 1 色は背景に使うので、残りは 3 色です。WASM-4 はパレットを毎フレーム書き換えられるので、1 つ目と 2 つ目の連符の N に合わせて、その色を Web 版のダークテーマの色に入れ替えています。3 つ目の連符と文字は白で描きます。4 連と 3 連なら、Web 版と同じ赤い四角と黄色い三角になります。  
多角形は line() でつなぎ、頂点は oval() で描きます。鳴った頂点は約 0.22 秒（13 フレーム）かけて大きな丸から元に戻ります。これも Web 版の光り方に合わせました。中央の拍の数字は、組み込みの 8×8 フォントでは小さいので、3×5 の数字を 3 倍の四角で描いています。

## **操作：ボタン 2 つに機能を割り振る**

使えるのは十字キーとボタン 2 つだけです。上下で項目を選び、左右で値を変え、A で再生と停止。B は選んでいる項目によって役割を変えています。

* BPM の行：B を押して離すとタップテンポ、B を押しながら左右で ±10
* 連符の行：B でその連符を BPM の基準にする

タップと「押しながら左右」を区別するため、B を押している間に十字キーが押されたかどうかを覚えておき、押されなかったときだけ、離したときにタップとして数えます。タップの時刻は押した瞬間のフレームを使い、直近 4 回の間隔の平均から BPM を出します（Web 版と同じ計算です）。

## **保存**

WASM-4 の保存領域（diskw）に、BPM・基音・連符・基準・プリセットを 11 バイトで書いています。先頭に目印とバージョン番号を入れて、読み込んだ値は必ず範囲内に収めます。値を変えるたびに書くのではなく、操作が止まってから 0.75 秒後にまとめて保存しています。

## **テスト：ブラウザを使わずにフレームを回す**

音が正しい時刻に鳴っているかは、聴いて確かめるだけでは足りません。Node.js で .wasm を読み込み、WASM-4 の関数を記録用のダミーに差し替えて update() を 1 フレームずつ呼ぶ、小さなテスト環境を作りました。tone() が何フレーム目に、何 Hz で呼ばれたかを全部記録して、次のようなことを確かめています。

* 96 BPM・4:3 で 10 秒鳴らすと、4 連が 17 回、3 連が 13 回鳴る（音程は 880Hz と 660Hz）
* 各拍の誤差が 1 フレーム以内で、10 分後の 960 拍目も計算どおりのフレームで鳴る
* 1 周の頭では全部の連符のアクセントが同じフレームに揃う
* BPM の変更、タップテンポ（30 フレーム間隔で 120 BPM）、保存と読み込み、基準の切り替え、平均律
* 300 BPM・12 連でも止まらない

全部で 15 項目あり、ビルドのたびに数秒で終わります。画面の確認は、WASM-4 の HTML 書き出しを Playwright で開いてスクリーンショットを撮って行いました。
